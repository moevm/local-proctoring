# Local Proctoring

Расширение Google Chrome для локальной записи экрана, камеры и микрофона,
скачивания файлов и отправки в [proctoring](https://github.com/OSLL/proctoring).
Рабочий код — `client/`. Отдельный сервер расширения не нужен.
Версия: [VERSION](VERSION), изменения: [CHANGELOG](CHANGELOG.md).

## Установка и подключение

Нужен Google Chrome 134+. Распакуйте архив client, откройте `chrome://extensions`,
включите режим разработчика и загрузите каталог как распакованное расширение.
ID: `nlhjjbgkbfkopkigkbkojpkbffbkeohg`. Manifest key сохраняется при обновлении.

В `client/settings.json` сохраняйте video_settings и задайте параметры сервера:

```json
{
  "session_settings": {
    "server_connection": true,
    "server_video_upload": false,
    "local_video_saving": true,
    "server_url": "http://127.0.0.1:8000/api/remoteSessions"
  }
}
```

По умолчанию сервер используется для проверки обновлений, видео сохраняются локально.
Для отправки видео включите `server_video_upload: true` при `server_connection: true`.
`server_connection: false` отключает обращения к серверу полностью.
`local_video_saving: true` включает скачивание файлов на компьютер.

Production использует HTTPS. `host_permissions` в manifest разрешает origin сервера.
Backend разрешает точный extension origin через FRONTEND_ORIGINS либо все корректные
Chrome extension origin через ALLOW_ALL_EXTENSION_ORIGINS=true. Второй режим
расширяет доверие, но сохраняет авторизацию и проверку владельца.

## Запись и сохранение

1. Заполните данные сессии и предоставьте разрешения на экран, камеру и микрофон.
2. Запустите запись. Сеть и авторизация для локальной записи не нужны.
3. Не закрывайте и не обновляйте служебную вкладку. После остановки дождитесь
   завершения записи последнего чанка в OPFS.
4. При включённом локальном сохранении файлы скачиваются до обращения к серверу.
5. Для отправки войдите на сайт в том же профиле Chrome. Серверная сессия создаётся
   при отправке; сервер проверяет версию расширения.

Popup показывает политику версий информационно. Ошибка проверки не мешает записи.
Отправка живёт в служебной вкладке, закрытие popup её не отменяет.
Таймаут запросов и загрузки — 120 секунд.

«Мои записи» позволяет просмотреть и скачать OPFS-файлы без сети и без удаления
оригиналов. При ошибке отправки файлы доступны для скачивания и повтора.
После потери ответа проверяется серверный статус; сохранённые видео повторно
не отправляются. Ошибку запуска ML устраняет оператор без повторной загрузки.
После попытки отправки продолжение записи блокируется до её завершения.

Не удаляйте расширение, не меняйте ID и не очищайте данные с невыгруженными файлами.
Закрытие вкладки или браузера может потерять незаписанный хвост. Многочасовая запись
требует достаточного места и квоты OPFS. Локальное видео не доказывает непрерывность контроля.

Лимиты API: 8 GiB на файл, 16 GiB на запрос; ML по умолчанию скачивает до 4 GiB
на видео. Более крупные записи требуют согласования лимита ML и дискового места.

## Разработка и проверки

Из корня: `docker compose run --build --rm tests`.
Набор включает Prettier, ESLint, VERSION, unit, mock HTTP и Chrome UI.
Для unit: `docker compose run --build --rm tests npm run test:unit`.
Client не требует сборки. VERSION синхронизируется командами
`node scripts/sync-release-version.js` и `node scripts/check-release-version.js`.
