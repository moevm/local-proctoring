# Changelog — local-proctoring

Текущая версия — в [VERSION](VERSION). Подготовка ведётся в pre-release.
Правила: [правила проекта](docs/versioning.md).
Рабочий продукт — client; playground содержит исторические эксперименты.

## [Unreleased]

- CI: Chrome UI запускается только на pull_request; push сохраняет статические
  и модульные проверки. Push и PR не отменяют друг друга через concurrency.

- Согласованы инструкции запуска, тестирования и версий; добавлена карта документации,
  исторические отчёты отделены от актуальных команд.

### Работа расширения

- При открытии popup показывается результат проверки обновлений и HTTPS-ссылка
  на архив. Перед стартом серверная политика проверяется повторно; запрет нового
  старта не мешает отправить сохранённые видео.
- Микрофон записывается с камерой, а без камеры — с экраном. После подтверждённого
  сохранения пользователь видит сообщение об успехе.
- Отправка учитывает точный состав файлов и проверяет серверный статус после
  потери ответа. Неизвестное подтверждение не разрешает удаление оригиналов;
  продолжение записи заблокировано до завершения попытки отправки.
- Ошибки OPFS сохраняют индекс восстановления. «Мои записи» показывает также файлы
  без индекса, позволяет просматривать и скачивать их без удаления оригинала.
- Сетевые таймауты охватывают запрос и чтение JSON; ошибки доходят до popup.
- Синхронизация VERSION проверяет стабильный ID. Обновлены пользовательская
  и встроенная справка; удалены неиспользуемые функции выгрузки логов.

### Запись и восстановление

- Кнопки сохранения и нового старта блокируются до завершения финализации записи.
  Перезапуск расширения учитывает прерванную финализацию.
- Повреждённая история логов не мешает открытию popup. При ошибке storage буфер
  сохраняется для повтора; размер сохранённой истории ограничен 8 MiB.

### Тесты и CI

- Вместо старого Flask-сервера, Python-тестов и shell-runners используются
  unit-тесты node:test, HTTP-контракт mock API и UI-сценарии Playwright.
- Весь тестовый код приведён к ESM `.js`. Отдельно организованы страницы,
  пользовательские действия, окружение и fixtures. Unit-тесты исполняют исходные
  модули в изолированном VM-контексте без переписывания кода.
- Mock повторяет используемые маршруты, cookie-авторизацию, статусы и подтверждения
  веб-прокторинга. Для запуска не нужны backend, MongoDB и ML.
- Проверяются запись и аудиодорожки, отказы устройств и API, сохранность файлов,
  восстановление после перезапусков, обновления и просмотр локальных записей.
- Docker Compose запускает форматирование, ESLint, проверку версии и все тесты.
  Node, Chrome, Xvfb, ffprobe и зависимости входят в образ; CI использует тот же запуск.
  Команду можно заменить для выбора набора или отдельного сценария.
- Добавлены инструкция по устройству и расширению тестов, матрица покрытия
  и HTML / JSON / JUnit отчёты. Генерируемые результаты исключены из Git.

### Документация

## [3.1.0] — 2026-10-16

Первая согласованная версия с proctoring / proctoring-ml 3.1.0.
Прежний manifest был 2.0.3. Выравнивание номера не означает переписывания расширения.
Версия Chrome manifest генерируется из VERSION, version_name удалён; key и ID сохранены.

### Добавлено

- Один редактируемый VERSION в каждом независимом проекте; только собственные metadata
  генерируются локально. Текущие номера в README заменены ссылками.
- Рабочая локальная ветка переименована в pre-release; принята схема main / dev / pre-release / release.

- Общие VERSION, README, CHANGELOG и AGENTS для связанного комплекта.
- Стабильный публичный key для одинакового extension ID при распространении архивом.
- Проверка серверного status/:id перед повторной отправкой после потери ответа.
- Модульная отправка, сериализация OPFS writer и ожидание завершения скачивания.

### Исправлено

- Согласованы cookie-авторизация, MIME WebM и точный FRONTEND_ORIGINS основного backend.
- Отправка перенесена из popup в служебную вкладку; ошибки HTTP / JSON не считаются успехом.
- Оригиналы сохраняются при отказе API / очереди / отмене скачивания.
- Обновление версии и таймер больше не удаляют неотправленные записи / метаданные.
- Stop ожидает последний dataavailable и все write / close; проверяется квота.
- Камера записывает микрофон, отсутствие микрофона не приравнивается к отсутствию камеры.
- Исправлены cleanup потоков / AudioContext, async runtime messages, небезопасный HTML уведомлений,
  UTC-метаданные и пустое отчество без фиктивной заглушки.
- Убран unload; pagehide не обещает завершить асинхронную запись при уничтожении вкладки.

### Проверено и ограничения

- 14 клиентских Node-тестов; настоящий Chrome / OPFS / multipart / ML / просмотр обоих видео.
- Две записи расширением сохранены на общем review-стенде; подробности в основном proctoring.
- Многочасовые записи, hard-kill, production HTTPS и все варианты отказов требуют отдельного E2E.
- Историческая техническая детализация сохранена в client/API-COMPATIBILITY.md.
