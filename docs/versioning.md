# Версия проекта и ветки

## Независимый источник

Единственный редактируемый номер этого проекта — корневой [VERSION](../VERSION),
формат MAJOR.MINOR.PATCH без суффиксов. Версии других проектов не являются источником
этого номера: их файлы не читаются, не копируются и не перезаписываются.
Репозиторий можно использовать отдельно, без соседних checkout.

Сейчас всем трём связанным проектам назначен одинаковый начальный номер, но далее
версии могут повышаться независимо. Совместимость определяется API-контрактом и
проверками, а не равенством версий. GitHub-теги не заменяют локальный VERSION.

## Изменение и проверка

Измените VERSION только в этом репозитории. Затем из его корня:

~~~sh
node scripts/sync-release-version.js
node scripts/check-release-version.js
~~~

Синхронизация обновляет только локальные генерируемые метаданные:

- client/manifest.json: version; избыточный version_name удаляется.
- key, ID, разрешения, пользовательские данные и зависимости не изменяются.

Проверка без записи — check-release-version.js; регрессии:
node --test scripts/tests/releaseVersion.test.js.
Все входные файлы проверяются до первой записи. Зависимости, .env, CHANGELOG
и исходники приложения синхронизация не меняет.

README и инструкции ссылаются на VERSION и не требуют замены номера при повышении.
Разделы CHANGELOG содержат исторические версии: их заголовки не переименовываются,
для следующей версии создаётся новый раздел. Текущую работу описывайте в Unreleased.
PATCH — совместимое исправление, MINOR — новая совместимая возможность,
MAJOR — несовместимый контракт или необходимые миграции.
Версии зависимостей, Python, PaddleOCR, manifest_version и Docker Compose — не версия проекта.

## Основные ветки

- main — основная линия.
- dev — разработка.
- pre-release — подготовка и проверка следующей версии.
- release — линия опубликованных / развёртываемых релизов.

Имя ветки не является суффиксом версии и не разрешает публикацию.
Переименование текущей локальной ветки не меняет удалённые ветки и не выполняет merge.
Отсутствующие main / dev / release не создавайте на произвольном коммите:
сначала нужно выбрать их базу. Существующие ветки сохраняются.

## Обновление и безопасность

Фиксируйте фактические тесты, совместимые версии соседних сервисов и непроверенные
сценарии в CHANGELOG / отчётах. Номер без суффикса не означает опубликованный релиз.
Даты подготовки — Europe/Moscow. Сохраняйте dirty worktree, БД, видео, OPFS и кеши.
Не пересобирайте контейнеры и не прерывайте запись / анализ ради смены номера документации.
Для расширения сохраняются key / ID, обновление выполняется вне записи и отправки.

Коммиты, push, GitHub tags / releases, удалённые ветки и распространение архивов —
только по отдельному прямому разрешению пользователя.
